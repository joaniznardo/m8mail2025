1. El Correu Electrònic

Una mica d'història

Història breu

  • 1971 — Ray Tomlinson envia el primer email (ARPANET)
  • 1982 — Es publica l'RFC 821 (SMTP)
  • 1988 — POP3 (RFC 1081)
  • 1996 — IMAP4 (RFC 2060)
  • 2003 — SPF (RFC 4408)
  • 2011 — DKIM (RFC 6376)
  • 2012 — DMARC
  • 2024 — JMAP (RFC 8620) guanya tracció

Arquitectura del correu

  ┌─────────┐         ┌─────────┐         ┌─────────┐         ┌─────────┐
  │   MUA   │──SMTP──▶│   MTA   │──SMTP──▶│   MTA   │──LMTP──▶│   MDA   │
  │ (client)│  :587   │ (enviant)│  :25    │(receptor)│        │(entrega) │
  └─────────┘         └─────────┘         └─────────┘         └────┬────┘
   Thunderbird         Postfix             Postfix                  │
   Roundcube                                                       ▼
   swaks                                                    ┌─────────┐
                                                            │  Mailbox│
                                    ┌─────────┐             │ (buzó)  │
                                    │   MUA   │◀──IMAP/POP──┘─────────┘
                                    │(receptor)│    :993
                                    └─────────┘
MUA: Mail User Agent • MTA: Mail Transfer Agent • MDA: Mail Delivery Agent

Components clau

Servidor

  • Postfix — MTA (SMTP)
  • Dovecot — MDA/IMAP/POP3
  • Rspamd — Anti-spam/DKIM
  • ClamAV — Antivirus

Client

  • Thunderbird — Desktop
  • Roundcube — Webmail
  • SOGo — Groupware
  • swaks — CLI debug

2. Protocols de Correu

SMTP, IMAP, POP3

SMTP — Simple Mail Transfer Protocol

  • Protocol d'enviament de correu
  • Basat en text (ASCII)
  • Model push
  • Definit a l'RFC 5321
Port 25Transfer (MTA→MTA)
Port 587Submission (STARTTLS)
Port 465Submission (TLS implícit)

S: 220 mail.alumnat.demoasixcloud2025.cat ESMTP
C: EHLO client.local
S: 250-mail.alumnat.demoasixcloud2025.cat
S: 250-STARTTLS
S: 250-AUTH PLAIN LOGIN
C: MAIL FROM:<alumne1@alumnat.demoasixcloud2025.cat>
S: 250 2.1.0 Ok
C: RCPT TO:<alumne2@alumnat.demoasixcloud2025.cat>
S: 250 2.1.5 Ok
C: DATA
S: 354 End data with <CR><LF>.<CR><LF>
C: Subject: Hola!
C: Primer missatge de prova.
C: .
S: 250 2.0.0 Ok: queued
C: QUIT

IMAP — Internet Message Access Protocol

  • Protocol de lectura de correu
  • Missatges romanen al servidor
  • Suporta carpetes i cerca
  • Sincronització multi-dispositiu
  • Definit a l'RFC 9051 (IMAP4rev2)
Port 143IMAP (STARTTLS)
Port 993IMAPS (TLS implícit)

POP3 vs IMAP

CaracterísticaPOP3IMAP
EmmagatzematgeClient (descarrega)Servidor
Multi-dispositiuNoSí
CarpetesNoSí
Cerca al servidorNoSí
Ample de bandaBaix (un cop)Major (sync)
Ports110 / 995143 / 993
Ús recomanatDispositiu únicGeneral

JMAP — El futur?

  • JSON Meta Application Protocol (RFC 8620)
  • Substitueix IMAP amb una API JSON sobre HTTP
  • Més eficient per a clients web i mòbils
  • Sincronització d'estat en lloc de comandes
  • Stalwart el suporta nativament

{
  "using": ["urn:ietf:params:jmap:core", "urn:ietf:params:jmap:mail"],
  "methodCalls": [
    ["Email/query", {"filter": {"inMailbox": "inbox-id"}}, "0"],
    ["Email/get", {"#ids": {"resultOf": "0"}}, "1"]
  ]
}

3. DNS i el Correu

MX, A, PTR i més

Registres DNS essencials

TipusNomValorFunció
MXalumnat.demo...10 mail.alumnat.demo...On enviar el correu
Amail.alumnat.demo...10.26.50.10IP del servidor
PTR10.50.26.10.in-addr.arpamail.alumnat.demo...Resolució inversa
TXTalumnat.demo...v=spf1 mx ~allSPF
TXTmail._domainkey.alumnat...v=DKIM1; k=rsa; p=...DKIM
TXT_dmarc.alumnat...v=DMARC1; p=none...DMARC

Flux de resolució DNS per enviar un correu

alumne1 vol enviar a profe1@professorat.demoasixcloud2025.cat

1. MTA consulta: dig professorat.demoasixcloud2025.cat MX
   → 10 mail.professorat.demoasixcloud2025.cat

2. MTA consulta: dig mail.professorat.demoasixcloud2025.cat A
   → 10.26.50.20

3. MTA connecta a 10.26.50.20:25 via SMTP

4. El receptor verifica:
   - SPF: L'IP d'origen està autoritzada?
   - DKIM: La signatura del missatge és vàlida?
   - DMARC: Què fer si SPF/DKIM fallen?

Verificar DNS amb dig


# Registre MX (on va el correu)
dig @10.26.50.2 alumnat.demoasixcloud2025.cat MX

# Registre A (IP del servidor)
dig @10.26.50.2 mail.alumnat.demoasixcloud2025.cat A

# Registre PTR (resolució inversa)
dig @10.26.50.2 -x 10.26.50.10

# Registre SPF
dig @10.26.50.2 alumnat.demoasixcloud2025.cat TXT

# Registre DKIM
dig @10.26.50.2 mail._domainkey.alumnat.demoasixcloud2025.cat TXT

# Registre DMARC
dig @10.26.50.2 _dmarc.alumnat.demoasixcloud2025.cat TXT

4. TLS i el Correu

Xifrat de les comunicacions

STARTTLS vs TLS implícit

STARTTLS (explícit)

  • Comença en text pla
  • Negocia TLS amb STARTTLS
  • Ports 587 (SMTP), 143 (IMAP)
  • Vulnerable a downgrade attack

TLS implícit

  • TLS des del primer byte
  • No hi ha fase en text pla
  • Ports 465 (SMTPS), 993 (IMAPS)
  • Més segur

Certificats Let's Encrypt

Validació DNS amb Cloudflare: L'autoritat certificadora verifica que controles el domini creant un registre TXT temporal a la zona DNS. 

# Generar certificat amb acme.sh + Cloudflare DNS
export CF_Token="el_teu_token"
acme.sh --issue --dns dns_cf \
    -d alumnat.demoasixcloud2025.cat \
    -d mail.alumnat.demoasixcloud2025.cat \
    --server letsencrypt --keylength 4096
        

# Verificar certificat amb openssl
openssl s_client -connect 10.26.50.10:465 -quiet
openssl s_client -starttls smtp -connect 10.26.50.10:587

Sense TLS vs amb TLS

Sense TLS (Etapa 1): Les credencials viatgen en text pla. Un atacant amb accés a la xarxa pot capturar usuaris i contrasenyes. 

# Captura tcpdump sense TLS — es veu TOT:
AUTH LOGIN
YWx1bW5lMUBhbHVtbmF0Lg==    (base64 de l'usuari)
QWx1bW5lMS4yMDI1            (base64 de la password!)
Amb TLS (Etapa 2): Tot el tràfic està xifrat. La captura només mostra dades binàries il·legibles.

5. Autenticació del correu

SPF, DKIM, DMARC

SPF — Sender Policy Framework

Pregunta: "Qui pot enviar correu en nom de alumnat.demoasixcloud2025.cat?"

DNS TXT: alumnat.demoasixcloud2025.cat → "v=spf1 mx ~all"

  ┌──────────┐     SMTP      ┌──────────┐
  │ Emissor  │──────────────▶│ Receptor │
  │ IP: X.X  │               │          │
  └──────────┘               └────┬─────┘
                                  │
                          Consulta SPF:
                          "L'IP X.X està
                           autoritzada per
                           enviar des d'aquest
                           domini?"
                                  │
                           ┌──────▼──────┐
                           │ Sí → Accepta│
                           │ No → ~all   │
                           │   (softfail)│
                           └─────────────┘

SPF — Sintaxi


v=spf1 mx ~all
│      │   │
│      │   └── ~all: softfail (marcar però no rebutjar)
│      │       -all: hardfail (rebutjar)
│      │       +all: pass (acceptar tot — MAI fer!)
│      │
│      └── mx: les IPs dels registres MX estan autoritzades
│
└── v=spf1: versió del registre SPF

Altres mecanismes: ip4:X.X.X.X, include:domini.com, a

DKIM — DomainKeys Identified Mail

  ┌──────────┐                              ┌──────────┐
  │ Emissor  │                              │ Receptor │
  │   MTA    │                              │   MTA    │
  └────┬─────┘                              └────┬─────┘
       │                                         │
  1. Signa el missatge                    3. Obté clau pública
     amb clau PRIVADA                        del DNS:
       │                                    mail._domainkey.
       ▼                                    alumnat.demo...
  ┌──────────┐        SMTP          ┌──────▼──────┐
  │ Missatge │─────────────────────▶│  Verifica   │
  │ + DKIM-  │                      │  signatura  │
  │ Signature│                      │  amb clau   │
  └──────────┘                      │  pública    │
                                    └─────────────┘

DKIM — Capçalera de signatura


DKIM-Signature: v=1; a=rsa-sha256; c=relaxed/relaxed;
    d=alumnat.demoasixcloud2025.cat; s=mail;
    h=from:to:subject:date:message-id;
    bh=abc123...=;    ← hash del cos
    b=xyz789...=;     ← signatura digital

d= domini • s= selector • h= capçaleres signades • b= signatura

DMARC — Domain-based Message Authentication


_dmarc.alumnat.demoasixcloud2025.cat TXT
    "v=DMARC1; p=none; rua=mailto:postmaster@alumnat.demoasixcloud2025.cat"

Polítiques:
  p=none       → Només monitoritzar (informes)
  p=quarantine → Marcar com a spam si falla
  p=reject     → Rebutjar el missatge
DMARC = SPF + DKIM + Política
Diu als receptors què fer quan SPF o DKIM fallen, i on enviar informes.

Verificació amb swaks

      --server 10.26.50.10 --port 587 --tls \

6. Servidors de Correu

DMS, Stalwart, Mailcow

docker-mailserver (DMS)

  • 1 contenidor amb tot integrat
  • Postfix + Dovecot + Rspamd
  • Configuració per env vars i fitxers
  • CLI: setup email add
  • Sense interfície web pròpia
  • Lleuger i ben documentat

# docker-compose.yml
environment:
  OVERRIDE_HOSTNAME: mail.alumnat...
  ENABLE_RSPAMD: 1
  SSL_TYPE: manual
  SSL_CERT_PATH: /etc/ssl/mail/fullchain.pem
  SSL_KEY_PATH: /etc/ssl/mail/key.pem

Stalwart Mail Server

  • 1 contenidor, escrit en Rust
  • Tot integrat (SMTP, IMAP, JMAP)
  • Configuració per TOML o web admin
  • Interfície web d'administració
  • Genera DKIM/SPF/DMARC automàticament
  • Suporta CalDAV/CardDAV

# config.toml
[server]
hostname = "mail.professorat..."

[server.listener.smtp]
bind = ["0.0.0.0:25"]
protocol = "smtp"

[certificate.default]
cert = "/etc/ssl/mail/fullchain.pem"
private-key = "/etc/ssl/mail/key.pem"

Mailcow

  • ~12 contenidors (microserveis)
  • Postfix + Dovecot + Rspamd + SOGo
  • MariaDB + Redis
  • Web UI completa
  • Configuració via mailcow.conf
  • Gestió via docker-compose

# Desplegar Mailcow
git clone https://github.com/\
  mailcow/mailcow-dockerized
cd mailcow-dockerized
./generate_config.sh
docker compose up -d

Etapa 6 Codi de la connexió veth


# 1. Crear el parell veth (host ↔ contenidor)
ip link add mcow-alumni-h type veth peer name eth2

# 2. Connectar un extrem al bridge de Mailcow
BRIDGE=$(docker network inspect mailcowdockerized_mailcow \
    -f '{{.Options.com.docker.network.bridge.name}}')
ip link set mcow-alumni-h master "$BRIDGE"
ip link set mcow-alumni-h up

# 3. Moure l'altre extrem al namespace del contenidor
PID=$(docker inspect -f '{{.State.Pid}}' \
    clab-mailserver-lab-mail-alumni)
ip link set eth2 netns "$PID"

# 4. Configurar IP dins el contenidor
nsenter -t "$PID" -n ip addr add 172.22.1.30/24 dev eth2
nsenter -t "$PID" -n ip link set eth2 up

Etapa 6 Regles iptables (DNAT)


# Dins el namespace de mail-alumni:
# Redirigir ports d'entrada cap als contenidors Mailcow

# SMTP (transfer i submission)
iptables -t nat -A PREROUTING -i eth1 -p tcp --dport 25 \
    -j DNAT --to-destination 172.22.1.253:25
iptables -t nat -A PREROUTING -i eth1 -p tcp --dport 587 \
    -j DNAT --to-destination 172.22.1.253:587

# IMAP
iptables -t nat -A PREROUTING -i eth1 -p tcp --dport 143 \
    -j DNAT --to-destination 172.22.1.250:143
iptables -t nat -A PREROUTING -i eth1 -p tcp --dport 993 \
    -j DNAT --to-destination 172.22.1.250:993

# Web UI
iptables -t nat -A PREROUTING -i eth1 -p tcp --dport 8080 \
    -j DNAT --to-destination 172.22.1.11:8080

# MASQUERADE perquè els contenidors vegin la IP del gateway
iptables -t nat -A POSTROUTING -o eth2 -j MASQUERADE

Etapa 6 Notes tècniques importants

No fer docker restart en contenidors Containerlab! Trenca els enllaços de xarxa (veth pairs). Utilitzar docker stop/start o reiniciar serveis interns.
DH params: Mailcow requereix paràmetres Diffie-Hellman de 2048 bits. Amb 1024 bits, OpenSSL rebutja la connexió: "dh key too small".
Autenticació Dovecot: Mailcow usa una cadena Lua → HTTPS → PHP → MySQL. La comanda doveadm auth test pot ser enganyosa (usa auth_passdb_lookup en lloc de auth_password_verify).

SPF amb ip4: Al laboratori cal ip4:10.26.50.0/24 perquè els servidors envien des d'IPs de la xarxa del lab, no des de les IPs públiques dels registres MX.

DMS (Rspamd) — Particularitats

  • Rspamd salta SPF/DMARC per usuaris autenticats (is_skip_local_or_authed()). Cal forçar: check_authed = true a spf.conf i dmarc.conf
  • settings.conf per defecte limita a DKIM signing. Cal sobreescriure amb un apply {} buit
  • use_esld = false — Rspamd normalitza subdominis al eSLD per defecte (alumnat.demo... → demoasixcloud2025.cat). Cal desactivar-ho
  • local_networks = "127.0.0.0/8" — Perquè les IPs del lab (10.26.50.x) es tractin com a externes
  • La capçalera Authentication-Results requereix un plugin Lua personalitzat per mostrar correctament els resultats DKIM

Stalwart — Particularitats

  • API REST per gestionar DKIM: POST /api/dkim crea signatures, GET /api/dns/records/{domain} retorna registres DNS
  • Selector auto-generat: format YYYYMMr (ex: 202604r)
  • No afegeix Authentication-Results per entrega local — cal verificar DKIM/SPF amb eines externes (swaks + capçaleres)
  • Contrasenyes: requereixen prefix {PLAIN} a l'API
  • Autenticació: només accepta noms curts (profe1, no l'email complet)

Mailcow — Particularitats

  • DKIM automàtic: es genera al crear el domini via API o Web UI. Selector dkim, RSA 2048 bits
  • API REST completa: /api/v1/add/domain, /api/v1/add/mailbox, /api/v1/get/dkim/{domain}
  • Rspamd integrat amb configuració per defecte funcional (no cal els ajustos de DMS)
  • Web admin: admin / moohoo
  • Cadena d'autenticació: Dovecot → Lua → HTTPS → PHP → MySQL

Preguntes de reflexió i comprensió

Protocols i arquitectura

  1. Per què existeixen dos ports per a SMTP submission (587 i 465)? Quin és preferible i per què?
  2. Explica la diferència entre un MTA i un MDA. Quins programes fan cada rol a DMS, Stalwart i Mailcow?
  3. Per què IMAP ha desplaçat POP3 en la majoria d'entorns? En quin escenari encara podria ser útil POP3?
  4. Què passa exactament quan un MTA vol lliurar un correu a un domini desconegut? Quines consultes DNS fa i en quin ordre?

TLS i seguretat

  1. Què és un downgrade attack contra STARTTLS? Com es pot mitigar?
  2. Per què al laboratori (Etapa 1) es poden capturar credencials amb tcpdump? Què canvia a l'Etapa 2?
  3. Mailcow rebutja paràmetres DH de 1024 bits amb l'error "dh key too small". Per què és important usar 2048 bits o més?
  4. Quina diferència hi ha entre un certificat autosignat i un de Let's Encrypt des del punt de vista d'un client de correu?

SPF, DKIM i DMARC

  1. Si un domini té v=spf1 mx ~all però el correu s'envia des d'una IP que no és la del registre MX, quin serà el resultat SPF? I si fos -all?
  2. Per què al laboratori cal ip4:10.26.50.0/24 al registre SPF en lloc de només mx?
  3. Per què Rspamd (a DMS) salta la verificació SPF per a usuaris autenticats? Quins riscos comporta? Com ho hem solucionat?
  4. Quina és la diferència entre p=none, p=quarantine i p=reject a DMARC? Per què comencem amb p=none?
  5. Si un atacant falsifica el From: d'un correu, quina combinació de SPF+DKIM+DMARC ho detectaria?

Xarxes i Containerlab

  1. Per què docker network connect falla amb el contenidor mail-alumni? Quina és l'arrel del problema?
  2. Explica pas a pas com funciona la solució del veth pair: què fa cada comanda i per què és necessària.
  3. Per què cal MASQUERADE a eth2 de mail-alumni? Què passaria si no hi fos?
  4. Per què no es pot fer docker restart en un contenidor de Containerlab? Quina alternativa hi ha?
  5. Quina diferència hi ha entre un Linux bridge del host i el switch del laboratori (contenidor amb bridge-utils)?

Comparativa de servidors

  1. DMS usa 1 contenidor, Stalwart 1 i Mailcow ~12. Quins avantatges i inconvenients té cada aproximació?
  2. Stalwart genera DKIM automàticament. DMS requereix setup config dkim. Mailcow ho fa via API/UI. Quin enfocament prefereixes per a producció i per què?
  3. Per què Stalwart només accepta noms curts (profe1) per autenticar-se però DMS i Mailcow accepten l'adreça completa?
  4. Si haguessis de triar un servidor per a una empresa petita (10 usuaris) i un per a una universitat (5000 usuaris), quin triaries en cada cas? Justifica-ho.

swaks — Swiss Army Knife for SMTP


# Opcions principals
swaks --to <destinatari>      # Destinatari
      --from <remitent>       # Remitent
      --server <ip>           # Servidor SMTP
      --port <port>           # Port (25/587/465)
      --tls                   # Negociar STARTTLS
      --tlsc                  # TLS implícit
      --auth LOGIN            # Autenticació
      --auth-user <usuari>    # Usuari
      --auth-password <pass>  # Contrasenya
      --header "Subject: ..."  # Capçalera personalitzada
      --body "..."             # Cos del missatge
      --attach @fitxer.pdf     # Adjunt
